# Пин-понг: Кристальная защита

Учебная игра на Python и Pygame. Нужно удерживать шарик в прямоугольном поле,
открытом снизу, отражая его цельной платформой шириной **три клетки**.
За отражения игрок получает кристаллы и покупает камни для нижней границы.
Кристаллы одновременно являются очками и валютой: покупка уменьшает отображаемый баланс.
Отдельная строка «Всего заработано» сохраняет сумму наград за текущую партию.

## Запуск

Проверено на Windows с **Python 3.12**, Pygame 2.6.1. Docker не используется.
Зависимости устанавливаются только в локальное виртуальное окружение `.venv`.

Из папки проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если `.venv` уже создано и зависимости установлены, достаточно последней команды
или двойного щелчка по `run.bat`. Активация окружения не требуется.
На Linux/macOS: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.txt`
и `.venv/bin/python main.py`.

## Управление

| Клавиши | Действие |
| --- | --- |
| F5 | Начать новую партию из любого состояния, сбросив прогресс |
| ← / → или A / D | Двигать платформу |
| Пробел | Приостановить или продолжить игру |
| F3 | Купить один камень во время игры или паузы |
| Esc | Вернуться к подготовке, сбросить партию и разрешить изменение окна |
| Q или закрытие окна | Выйти |

Перед первым стартом и после Esc окно можно растягивать: игровая область изменяется
вместе с ним. Минимальный размер окна — 840 × 680. После F5 окно фиксируется,
в том числе на паузе и после проигрыша. При потере фокуса включается пауза;
продолжить можно пробелом.

## Награды и магазин

- Каждое отражение платформой: **10 кристаллов**.
- Каждый пятый удар за партию: дополнительно **20 кристаллов**, итого 30 за этот удар.
- Столкновения со стенами и камнями не дают валюту.
- Камни стоят **30, 50, 70, 90…**; формула: `30 + 20 × количество купленных камней`.
- При недостаточном балансе покупка ничего не меняет; сообщение показывает недостающую сумму.
- Каждый камень закрывает одну клетку снизу. Камни появляются попеременно у левой
  и правой стен, сужая проём к центру. Они остаются до конца партии и отражают шарик.
- Последние три клетки остаются открытыми: полностью устранить риск проигрыша нельзя.

Такая экономика награждает активную игру: первый камень доступен после трёх отражений,
а бонусы за пятый удар помогают оплачивать следующие, более дорогие покупки.
Шарик появляется в случайной позиции у верхнего края и сразу движется вниз.
Удар ближе к краю платформы направляет его в сторону; после каждого отражения
скорость немного растёт, но ограничена сверху. Когда шарик полностью выходит
через нижний проём, партия заканчивается.

## Структура и проверка

- `game.py` — геометрия, состояния, столкновения, начисление наград и покупки.
- `main.py` — окно, ввод, графика и игровой цикл.
- `tests/test_game.py` — проверки физики, экономики, состояний и клавиш.
- `requirements.txt` — зафиксированная зависимость.
- `run.bat` — запуск через `.venv` в Windows.

Все функции снабжены русскими поясняющими docstring-комментариями.
Физика обновляется небольшими шагами, чтобы шарик не пролетал сквозь препятствия.
Она отделена от графики: правила можно проверять без настоящего окна.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Графическая часть использует документированные [режимы окна Pygame](https://www.pygame.org/docs/ref/display.html).

## Теоретический вопрос: парадигмы программирования

**Парадигма программирования** — подход к организации программы: как описываются
данные, действия над ними и порядок выполнения. Язык может поддерживать несколько
парадигм одновременно; Python — мультипарадигменный язык.

**Императивное программирование** описывает последовательность команд, которые
изменяют состояние программы. Примеры: присвоить скорость, изменить координаты,
уменьшить баланс после покупки. Процедурный подход — разновидность императивного:
команды объединяются в функции и процедуры, каждая решает отдельную задачу.
В игре методы `update()` и `_move_ball()` содержат последовательные шаги расчёта.

**Объектно-ориентированное программирование (ООП)** организует программу вокруг
объектов, объединяющих данные и поведение. Основные понятия: инкапсуляция
(объединение состояния и операций с ним), абстракция (выделение существенных свойств),
наследование (создание класса на основе другого) и полиморфизм
(единый интерфейс для разных реализаций). В этом проекте `Game` хранит состояние
партии и управляет правилами, `Ball` описывает шарик, `App` отвечает за интерфейс.
Наследование для реализации игры не требуется: используется композиция —
приложение содержит объект игры, а игра содержит объект шарика.

**Функциональное программирование** строится на вычислении значений с помощью
функций, предпочтительно чистых: их результат зависит только от аргументов,
а внешнее состояние не изменяется. Для него характерны неизменяемые данные,
функции высшего порядка и композиция функций. Python поддерживает этот стиль
через обычные функции, `lambda`, `map`, `filter` и генераторные выражения.
Например, стоимость можно вычислить чистой функцией
`def price(n): return 30 + 20 * n`. В игре геометрия `Box` неизменяема,
но физика в целом реализована императивно, так как обновляет состояние.

**Декларативное программирование** описывает требуемый результат, а конкретный
порядок его получения определяет система. Пример — SQL-запрос, задающий,
какие строки нужны. Функциональный и логический подходы часто относят
к декларативным, хотя классификации частично пересекаются.

**Логическое программирование** описывает факты и правила, а ответ получается
логическим выводом. Типичный язык — Prolog. Например, вместо пошагового поиска
родственников задаются отношения «родитель» и правила «предок». Для данной игры
этот подход не используется.

**Событийное программирование** организует работу вокруг обработки событий:
нажатий клавиш, изменения окна, закрытия приложения. Это подход к управлению
выполнением, который сочетается с ООП и процедурным стилем. В игре
`handle_event()` реагирует на F5, F3, пробел и события окна, а цикл `run()`
между событиями обновляет физику и рисует кадры.

Таким образом, здесь сочетаются ООП для структуры, императивный стиль для физики
и событийный подход для взаимодействия с пользователем.
